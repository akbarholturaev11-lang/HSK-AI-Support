## Findings and mitigations implemented

1. An early generic prompt answered Tajik “HSK AI чист?” in Uzbek. Added explicit language-specific prompt guides, current-message language selection, and handoff for obvious wrong-language replies. Focused new Tajik tests against the real model produced Tajik output.
2. Some account login replies invented Telegram-ID sign-in steps. Generic login how-to now returns a localized FAQ requesting the affected client rather than inventing procedures.
3. An individual payment receipt/status question could receive generic AI guidance instead of an operator ticket. Personal account/payment verification now takes an explicit operator route before static FAQ or AI; mocked webhook tests include all three languages.
4. Some PWA outputs exposed internal PWA_AUTH_ENABLED. New system instruction and output guard reject raw internal feature flags/IDs. The guard is defense in depth, not proof against all hallucination.
5. R2 unavailable/malformed KB must fail closed. Removed fallback to stale hard-coded facts; webhook tests cover missing R2.
6. Paid backup requires separate BACKUP_ENABLED, BACKUP_BILLING_APPROVED, BACKUP_SPEND_CAP_VERIFIED and explicit AI_GATEWAY_ID plus AI_GATEWAY_BACKUP_ROUTE configuration. Call-count quotas are NOT USD hard caps. Cloudflare Gateway hsk-ai-support exists but has zero routes.

## Release blockers (not done)

- D1 ai_conversation migration remains only in schema.sql. Production D1 is unchanged.
- The four-hour KB agent is enabled, but an independent successful scheduled run proving backup creation and rollback has not yet been observed.
- Telegram BOT_TOKEN is still a plaintext Worker binding. It must be moved securely to secret_text with webhook verification; never show the credential.
- Real paid MiniMax model, image input routing, Cloudflare Unified Billing and actual $0.20/day + $3/month cost limits are unverified and NOT enabled.
- Full Telegram photos, end-to-end operator flow, limits, retention, real multilingual quality and rollback need staging checks. Separate owner approval required for billing and production deployment.

**Decision:** Keep PR #2 as a draft; do not merge or deploy yet.
